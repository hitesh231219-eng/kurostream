# KuroStream v2.0.0 — GitHub Repository Overhaul, CI/CD & Windows Desktop Release

Upgrade the KuroStream GitHub repository into a full-featured, verified open-source showcase, publish the **v2.0.0** Stable Release with ready-to-run Windows desktop packages, automate testing and native Windows `.exe` builds via GitHub Actions, and connect the in-app Desktop Setup Wizard directly to GitHub Release downloads.

## User Review & Critical Decisions

> [!IMPORTANT]

- **Confirmed Decision 1 — Windows Packaging Strategy**: Publish an immediate self-contained portable Windows ZIP bundle built from the refreshed desktop runtime alongside an automated native Windows CI workflow that compiles and attaches native `.exe` installers/portables directly to the release.
- **Confirmed Decision 2 — Repository Showcase & Automation**: Deliver a flagship repository front page (status badges, visual preview gallery, mirror directory, feature architecture breakdown, and self-hosting guide), a structured version changelog, standardized issue/contribution templates, and GitHub Actions pipelines for continuous testing, build validation, and Windows releases.
- **Confirmed Decision 3 — Release Version Tag**: Publish under tag **`v2.0.0`** as the official Stable Release (`KuroStream v2.0.0 — Full UI Customizer & Windows Desktop Edition`).
- **Confirmed Decision 4 — In-App Desktop Setup Routing**: Update the Desktop & Downloads modal so primary Windows download cards pull directly from the live **v2.0.0** GitHub Release asset endpoints while retaining local script launchers and in-browser desktop frame controls.

## 1. Overview & Core Concept

- **What It Does**: Transforms the KuroStream repository from a minimal code mirror into a polished developer and end-user hub backed by automated quality gates and first-class Windows desktop distribution—complete with direct release binaries hosted on GitHub instead of third-party file hosts.
- **Target Audience / Persona**:
  - **Windows Desktop Users** seeking a fast, trustworthy, one-click executable or portable desktop app straight from official GitHub Releases.
  - **Web & Self-Hosters** evaluating live deployment mirrors, checking build status, or cloning the project to run locally.
  - **Contributors & Returning Users** reviewing release history, visual previews, and clear contribution workflows.
- **Key Value**: Eliminates broken third-party file links, proves build health automatically on every commit, guarantees repeatable Windows `.exe` builds without manual local Wine workarounds, and aligns the live web app's download wizard with authoritative release assets.

## 3. Key Product Decisions & Trade-Offs

- **Decision 1 — Hybrid Immediate + Automated Native Windows Packaging**
  - *Chosen Approach*: Bundle and upload an immediate self-contained portable Windows archive built cleanly from the latest verified web & embedded-server output, **and** add an automated Windows CI workflow triggered on tag pushes and manual dispatch to compile and upload native `.exe` portable and installer executables to the `v2.0.0` release.
  - *Why*: Guarantees immediate downloadable Windows assets in GitHub Releases right now without waiting on Linux-side Wine resource-editing quirks, while producing authentic Microsoft Windows-compiled `.exe` binaries automatically inside the official release.
  - *Alternatives Considered*: Relying solely on third-party file hosting (breaks/expires frequently) or compiling `.exe` solely through Linux emulation layers (fragile icon/version embedding).

- **Decision 2 — Release-First Routing in the Desktop Setup Wizard**
  - *Chosen Approach*: Point primary binary download cards directly to versioned `v2.0.0` GitHub Release asset URLs alongside a direct "View All v2.0.0 Assets on GitHub" fallback link, while keeping lightweight local script downloads self-contained on the active web origin.
  - *Why*: Ensures users on any mirror (Vercel, Netlify, GitHub Pages, or local Electron) download large desktop binaries cleanly from GitHub's global CDN rather than straining static web hosting limits.
  - *Alternatives Considered*: Serving 100MB+ desktop bundles directly from static frontend hosting (exceeds host asset limits and slows page deployments).

- **Decision 3 — Continuous Verification Before Publishing**
  - *Chosen Approach*: Separate fast PR/push verification (typecheck, Vitest unit suite, production Vite build, embedded desktop server bundle check) from GitHub Pages deployment and Windows executable release automation.
  - *Why*: Keeps feedback fast on regular code edits, surfaces live green status badges on the repository front page, and ensures broken builds never reach release or live Pages.

### Data Model & State

- **Release Metadata Registry**: Centralized repository & release constants (`v2.0.0`, repository URL, direct release tag URL, and canonical downloadable asset URLs) shared cleanly across the Desktop Setup Wizard, deployment mirror metadata, and README documentation.
- **Wizard Modal State**: Tracks active tab selection (`Downloads`, `PowerShell`, `Desktop Mode`), PowerShell execution mode (`Standard` vs. `Policy Bypass`), clipboard copy confirmation state, and reactive active origin updates synced via custom deployment URL events.
- **Release Asset Integrity**: Refreshes the production web bundle, embedded desktop server bundle, portable Windows executable archive, and installer bundle from identical source state before publishing.

### Interactive Component & State Mapping

- **Primary Download Cards**: Each release card links cleanly to its corresponding **v2.0.0** GitHub Release asset with clear format metadata (`x64 · ZIP`, `x64 · EXE`, `Offline Script`, `Full Source`) plus an always-available fallback link to the Release `v2.0.0` overview page in case a user prefers inspecting checksums or choosing alternate formats.
- **Command Mode Switcher & Copy Control**: Switching between Standard and Policy Bypass immediately recomputes the PowerShell script command against the active host URL and updates explanatory helper copy; clicking Copy writes to clipboard and displays a timed verified confirmation state.
- **Desktop Frame Action & Hosting Card**: Toggling Desktop Mode updates the in-browser window wrapper state cleanly and closes the modal; clicking Open Standalone Tab or Release Notes opens cleanly in a new context without disrupting playback state.

### Key Sequences & Integrations

1. **Refresh & Local Packaging**: Compile production web UI and embedded desktop server bundle, validate Electron runtime contents (repackaging a complete Windows portable folder cleanly with custom icon and latest compiled application bundle), and archive both the portable Windows bundle and Windows setup bundle.
2. **Repository Upgrade & Push**: Add generated showcase artwork for the visual preview section, upgrade documentation (`README`, `CHANGELOG`, community templates), add CI and Windows Release workflows, update the Desktop Setup Wizard, verify all tests/typechecks/builds pass locally, and push cleanly to `main`.
3. **Release Creation & Windows `.EXE` Automation**: Create authenticated GitHub Release **`v2.0.0`** with structured release notes, upload the immediate portable Windows ZIP and setup archive as release assets, trigger the native Windows GitHub Actions workflow targeting tag `v2.0.0`, and verify live workflow progress so the native `.exe` builds attach directly to the release.
